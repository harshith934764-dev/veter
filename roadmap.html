THE VETER PROJECT · BUILD PLAN

One ecosystem.
Many ways to build.

Veter's long-term direction is an original programming language and a connected set of developer tools. This roadmap turns that ambition into practical stages, starting with a dependable language and compiler.

Honest status: This page describes the development plan, not a list of released features. A feature is only complete when it is implemented, tested and documented in a public release. Existing prototype capabilities remain version-specific.
FOUNDATION FIRST

01 · Veter Language

Make the language predictable, readable and independently designed.

  • Define a versioned language specification
  • Consistent values, types and operators
  • Functions, modules and clear scope rules
  • Useful errors with file and line information
  • Stable standard library and compatibility policy
FOUNDATION FIRST

02 · Compiler and Runtime

Build a reliable engine that can be tested and improved safely.

  • Lexer, parser and semantic validation
  • Well-defined intermediate representation
  • Runtime and standard library boundaries
  • Automated regression and conformance tests
  • Reproducible builds and release versioning
NEXT STAGE

03 · Veter Studio

A focused desktop workspace for writing, running and debugging .vtr projects.

  • Editor, project explorer and syntax highlighting
  • Diagnostics and compiler output panel
  • Run and debug workflows
  • Project templates and build settings
  • Windows packaging and installation
NEXT STAGE

04 · Developer Tools

Make projects easier to maintain and share.

  • Package and dependency manager
  • Formatter and linter
  • Test runner and documentation generator
  • Git-friendly project structure
  • Published examples and starter projects
LONG-TERM

05 · Web Development

Explore a coherent path from Veter code to web applications.

  • HTTP server and routing libraries
  • API and data validation tools
  • Database drivers and migrations
  • Authentication building blocks
  • Frontend integration experiments
LONG-TERM

06 · Veter AI

AI assistance should help developers understand and improve their code.

  • Explain selected code
  • Suggest fixes with user review
  • Generate tests and starter examples
  • Keep AI suggestions separate from compiler truth
  • Protect source code and user privacy
LONG-TERM

07 · Security and Quality

Build trust into the developer workflow.

  • Dependency risk reporting
  • Secure defaults and permission boundaries
  • Input validation guidance
  • Release checks and signed artifacts
  • Responsible vulnerability reporting
LONG-TERM

08 · Cloud and Community

Connect developers without making cloud services mandatory.

  • Online playground and shareable examples
  • Optional project sync and collaboration
  • Package registry and community templates
  • Hosting integrations and deployment guides
  • Community contributions and governance
DELIVERY ORDER

Build in stages, prove each stage works.

Stage A · Stabilize

Specify the core language and lock down compiler tests.

Stage B · Create

Make Studio useful with real compiler integration.

Stage C · Extend

Add packages, libraries and practical application tools.

Stage D · Connect

Explore web, AI and cloud features after the foundation is solid.

The order may change as engineering results and community feedback become clear. Reliability comes before feature count.

How progress will be measured

  • Every released feature has tests and documentation.
  • Examples run on the stated compiler version.
  • Breaking changes are recorded in release notes.
  • Security and compatibility are reviewed before stable releases.
  • Planned features are clearly labelled until they actually ship.
