THE VETER PLATFORM · PRODUCT DIRECTION

One .vtr language.
Build across the stack.

The long-term Veter vision is to let developers describe interfaces, application logic, data and services using one original language and a connected toolchain—not a collection of unrelated syntax layers.

Honest status: This page describes the engineering targets. The current public compiler is a Core 1.0 prototype, Studio has a limited browser preview, and the modules below are planned unless explicitly marked as prototype work. They are not production-ready services today.

The platform modules

Each module has a clear responsibility. They should share one language model and runtime rather than becoming separate languages.

01 · LANGUAGE ENGINECORE PROTOTYPE

Veter Compiler & Runtime

The foundation that reads .vtr source and executes supported programs.

  • Stable grammar, types and scope
  • Useful file-and-line diagnostics
  • Functions, modules and standard library
  • Debugger, breakpoints and stack traces
  • Long-term self-hosting research
02 · FRONTENDPLANNED

Veter Web

Build web pages and application screens with native Veter declarations.

  • Page and layout definitions
  • Text, colours, images and responsive layout
  • Forms, buttons and input controls
  • Navigation and reusable components
  • Browser rendering integration
03 · BACKENDPLANNED

Veter Server

Create backend services and APIs using the same .vtr project.

  • HTTP server and route definitions
  • Request and response handling
  • Input validation and error responses
  • Background tasks and service configuration
  • Deployment and observability tools
04 · DATAPLANNED

Veter Data

Give applications a consistent way to store and retrieve information.

  • Database connections and queries
  • Schema definitions and migrations
  • Transactions and data validation
  • Indexes and backup workflows
  • Secure configuration for credentials
05 · IDENTITYPLANNED

Veter Auth

Provide safe building blocks for user accounts and access control.

  • Registration and sign-in flows
  • Password hashing and session handling
  • Role- and permission-based access
  • Account recovery patterns
  • Secure defaults and audit events
06 · INTERFACEPLANNED

Veter UI

Reusable interactive components that work consistently across applications.

  • Buttons, forms and menus
  • State and event handling
  • Component composition and themes
  • Accessibility and keyboard support
  • Responsive behaviour
07 · ECOSYSTEMEARLY LOCAL TOOLING

Veter Package

Grow reusable libraries with a predictable project format.

  • Local project scaffolding and manifest validation
  • Future dependency resolution and lock files
  • Package discovery and versioning
  • Publisher verification and integrity checks
  • Registry only after safe local workflows

See package tooling status →

08 · DELIVERYPLANNED

Veter Build

Turn a .vtr project into a distributable application.

  • Project build configuration
  • Release and optimisation modes
  • Standalone Windows .exe output
  • Dependency bundling and asset handling
  • Reproducible builds and signing
09 · WORKSPACEIN PROGRESS

Veter Studio

A developer workspace that connects editing, compiler output and project tools.

  • Multi-file project explorer
  • Real compiler integration
  • Diagnostics and debugging panel
  • Run, build and test workflows
  • Windows installer and updates

Build order

We should prove each foundation before depending on it in a larger product.

Stage 1 · Language

Stabilise grammar, types, functions, modules, tests and diagnostics.

Stage 2 · Studio

Connect the real compiler, project workflow, debugger and build tools.

Stage 3 · Application stack

Develop UI, Web, Server, Data and Auth as integrated libraries and runtime services.

Stage 4 · Ship

Complete package distribution, standalone builds, signing and deployment workflows.

Engineering promise: A feature moves from planned to available only after implementation, automated tests, documentation and a published build. No fake buttons, simulated backends or claims of production readiness.
