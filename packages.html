Veter package tooling is taking its first steps. The local C++ tool can validate a package manifest and scaffold a starter project. Package installation and a public registry are not available yet.

How it should work

Keep the first version small, predictable and safe.

01 · PROJECT

One manifest

Each project describes its name, version, supported Veter version and dependencies in one file.

02 · DEPENDENCIES

Repeatable installs

A lock file records exact dependency versions and integrity hashes so another developer can reproduce the same dependency set.

03 · REGISTRY

Discover libraries

A future registry can list package owners, source repositories, releases, compatibility and security notices.

Proposed project manifest

Illustrative JSON only. The format is not yet accepted by a released tool.

{ "name": "hello-veter-app", "version": "0.1.0", "veter": "core-1", "entry": "src/main.vtr", "dependencies": { "sample/text-tools": "^1.2.0" } }
Design note: Package names should be unique and publisher-scoped. A package must declare its license, source URL and supported Veter versions before publication.

Proposed command experience

The local veter-pkg utility supports project creation and manifest validation. The other commands remain planned.

veter new my-app veter add sample/text-tools veter install veter list veter update veter remove sample/text-tools

Non-negotiable safety rules

A package manager must protect developers, not just make installation easy.

Integrity checks

  • Lock exact versions
  • Verify archive hashes
  • Reject corrupted downloads

Trusted publishing

  • Verify package ownership
  • Sign release metadata
  • Show source and license

Safe by default

  • No automatic install scripts
  • Review dependency changes
  • Warn about known vulnerabilities
Never install a package just because its name looks familiar. A future Veter registry should show the publisher, source repository, version, license and integrity status before installation.

Build it in stages

A realistic roadmap from a file format to a trusted ecosystem.

Manifest validator and project scaffolder

Implemented in the local veter-pkg utility: validate metadata and create a starter project without downloading anything.

Local package cache

Support local archives and deterministic lock files before introducing a public registry.

Registry and publishing

Add verified publisher accounts, immutable releases, checksums and moderation/reporting.

Dependency security

Add vulnerability advisories, package deprecation and safe update workflows.

Help shape the proposal

Review the design and share feedback before implementation begins.
