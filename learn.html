01 · Getting started

What is Veter?

Veter is an independent programming-language project with its own command-style syntax and compiler. Its goal is to make code approachable and readable. The examples below follow the syntax visible in the current Veter compiler source; features that are not implemented are clearly identified.

Readable commandsWrite instructions such as say, make, and check.
Compiler-poweredThe compiler translates supported Veter statements into executable instructions.
Learn by buildingStart with values and expressions, then combine them into programs.
Growing projectThe language and website-building workflow can expand as the compiler gains features.
You do not need to memorize everything. Read one example, understand what each line does, then change a value and try again.
02 · First program

Your first Veter program

Use say to display a value. Text must be placed inside quotation marks.

hello.vtr
say "Hello from Veter!"
say "I am learning to code."

What happens? Each say statement displays one line of output. In this compiler, show and print are also accepted output commands.

03 · Values & variables

Store information with make

A variable is a named place where a program keeps a value. Veter uses make followed by a name and a value.

variables.vtr
make learner "Harshith"
make score 95
say learner
say score

Here, learner stores text and score stores a whole number. Use set as an alternative to make in the current compiler.

Current compiler note: the documented core value types are integers and strings. Decimal numbers, lists, objects, and other advanced data types should not be assumed to work unless added to a later compiler version.
04 · Expressions

Do calculations

Veter supports arithmetic expressions with parentheses and normal operator precedence.

math.vtr
make apples 10
make oranges 5
make total apples + oranges
make result (total * 2) - 4
say total
say result
OperatorMeaningExample
+Addition; also joins two strings5 + 2
-Subtraction5 - 2
*Multiplication5 * 2
/Integer division5 / 2
%Remainder5 % 2
( )Group an expression(5 + 2) * 3

Multiplication, division, and remainder are evaluated before addition and subtraction. Division by zero produces a compiler/runtime error.

05 · Input

Ask the user for information

Use take followed by a variable name. The program reads a line of input and stores it as text.

ask.vtr
say "What is your name?"
take name
say "Welcome, " + name

ask is also accepted as an alternative to take. Input is stored as a string; convert or validate it only with functionality your compiler supports.

06 · Conditions

Make decisions with check

A condition lets a program choose which instructions to run. Use otherwise for the alternative path and finish to close the decision block.

decision.vtr
make score 82
check score >= 50
  say "You passed!"
otherwise
  say "Try again."
finish
ComparisonMeaning
==Equal to
!=Not equal to
<Less than
<=Less than or equal to
>Greater than
>=Greater than or equal to

The condition body is indented here to make it easier to read. The compiler uses otherwise and finish to identify the block.

07 · Repetition

Repeat instructions

Use repeat N times to run a block a fixed number of times. Close it with end repeat.

repeat.vtr
repeat 3 times
  say "Practice makes progress."
end repeat

This displays the message three times. The current compiler accepts a whole-number repeat count from 0 to 1,000,000.

08 · Functions

Reuse instructions with functions

A function is a named group of instructions. In the current compiler, define one with do, close it with end, and call it with run.

function.vtr
do welcome
  say "Welcome to Veter!"
end

run welcome
run welcome
This version supports simple named function definitions and calls. Function parameters, return values, and local scopes are not shown as supported by the current compiler source.

Veter syntax is useful because the command names describe the action: make stores, say displays, take reads, check compares, and repeat repeats. This can make small programs easier to scan while you are learning.

10 · Website-building workflow

Build a simple web page with Veter

The Veter website-builder path in the project source uses readable page-building commands. This is a separate website-generation workflow from the core bytecode language examples above.

hello_site.vtr
make a website called "My First Site"
set page title "Welcome to my site"
set background color light blue
set text color dark blue
set font "Arial"
center content
show a title "Hello, world!"
show a subtitle "Built with Veter"
show text "I am learning to create websites."
add a text box called "Your name"
add a button "Say hello"
when button "Say hello" show alert "Hello from Veter!"
add a link "Visit Veter" "https://example.com"

What these commands do:

  • make a website called starts a website project.
  • set page title, set background color, set text color, and set font configure the page.
  • show a title, show a subtitle, and show text add content.
  • add a text box, add a password box, and add a checkbox add basic form controls.
  • add a button adds a button; the matching when button ... show alert ... line sets its alert message.
  • add a link adds a link that opens in a new tab.
Website-builder commands are limited to the commands implemented in the current source. This example demonstrates the supported page-generation workflow; it does not imply that Veter already provides full-stack hosting, database access, authentication, REST API routing, or production deployment.
11 · Compile & run

Run a Veter program

  1. Save your source code with a .vtr extension, for example hello.vtr.
  2. Open a terminal in the folder containing your Veter compiler.
  3. Run the compiler with your source file.
  4. Read the output or any compiler error, then fix and run again.
Terminal · example
veterc hello.vtr

The exact executable name and command may differ depending on how Veter was built and installed. Follow the command shown by your distributed compiler package.

12 · Learn honestly

What is supported now?

Good documentation tells learners what works today and what is still being developed.

Core compiler source demonstratesInteger and string values, variables, input, arithmetic, comparisons, if/otherwise, repeat loops, simple functions, bytecode listing, and VM execution.
Website builder source demonstratesPage title and style settings, text and headings, basic form controls, buttons, alert actions, and links.
Do not advertise planned capabilities as finished features. Database integration, full-stack application routing, secure authentication, API hosting, advanced data structures, and other features should be marked “Coming Soon” unless they are implemented and tested in the released compiler.
